# AI Skope — product spec (as understood after wave 1)

Status: design wave complete (2026-09-04). This document captures what the
extension is, every decision taken so far, and the assumptions the
implementation waves should build on. The visual kit lives in `design/`; the
server plan in `docs/SERVER-PLAN.md`.

## 1. What it is

AI Skope is a Chrome extension that turns any page into something you can *aim*
at. Once enabled it splits the browser canvas in two:

- **Content Pane** (left) — the real page for the tab's URL, untouched.
- **AI Pane** (right, full height, 320–640 px, default 400) — a chat that knows
  what's on the page. You pick an element, drag-select text, or add a local file,
  and it lands in the conversation as context.

The AI Pane does not call AI providers itself by default. It talks to the
**AI Skope Server (AISS)**, a local Go server that drives coding agents already
installed on the machine (Claude Code, Codex, pi, omp, opencode) and can read
folders the user allowed. That is what makes the primary use case possible:
**asking about local HTML / Markdown files, repos and notes**, not only web pages.

Direct provider API keys remain supported as a secondary source.

## 2. Layout and anatomy

```
┌──────────────────────────────────┬──┬──────────────────────────────┐
│ Content Pane (real page)         │▏ │ Top bar: ◎ AI Skope   + ↺ ⚙  │
│                                  │▏ │ Tabs: Chat | Notes (3)        │
│  · pick mode: amber reticle      │▏ │ Thread (user bubbles right,   │
│    outline + mono tag            │d │   assistant transcript left,  │
│  · text selection: floating      │i │   context chips on messages)  │
│    toolbar                       │v │ Status strip (only when off)  │
│  · toast / pick hint at bottom   │  │ Composer: tray of chips       │
│                                  │  │   3-line field                │
│                                  │  │   [pick][select][file][model]  [send] │
│                                  │  │   hints … Clear chat          │
└──────────────────────────────────┴──┴──────────────────────────────┘
```

**Top bar** = identity + navigation only: brand, **New chat**, **History**,
**Settings**. Brand name collapses to the mark under 350 px.

**Composer** = everything about *this* message: context tray, textarea (min 3
rows, grows to 8; ⏎ sends, ⇧⏎ newline), tools **Pick element** (⌘⇧K),
**Select text** (⌘⇧S), **Add file** (⌘⇧F), the **model chip**, and **Send**.
The hint row carries the shortcuts and a low-emphasis **Clear chat** at its
right end (far from Send).

### Context types (chips)
| type | how it's added | chip shows | payload to the model |
|---|---|---|---|
| element | pick mode, click | reticle · `article.pg-tier.featured` · `320 × 412` | selector, trimmed outerHTML, innerText, rect |
| text | drag-select → **Add to chat / Ask… / Save note** | quote glyph · first ~80 chars | the selection, surrounding block for context |
| file / folder | Add file → server picker | folder glyph · `README.md` · `~/dev/finme · 12 KB` | path (the runtime reads it inside an allowed folder) |
| page (implicit) | per "Page access" setting: Ask / Always / Never | — | URL, title, readable text |

### Pick mode
Cursor becomes a crosshair; hovered element gets a 2 px amber outline with
corner ticks, a floating mono tag `<selector> · w × h`, the rest of the page is
dimmed; a hint pill explains "Click an element to add it · esc cancel". Click adds
the chip and exits. Element identity = a stable CSS selector (id / classes /
nth-child), generated by the content script.

## 3. Chats, history, notes

- **One active chat + History.** No tabs, no forking. New chat archives the
  current conversation (never destroys). Clear chat = the same action from the
  composer, with **Undo**. Delete lives in History, with Undo.
- History groups chats **This page → This site → Everywhere**, rows show favicon
  tile, auto-title from the first message, runtime/model glyph + name, message
  count, time (+ host in Everywhere). Searchable. Local-file chats appear with an
  `MD` tile and the path.
- A chat is created on its first message; its title is that message (≤ 60 chars).
- Assistant messages carry a header `AI Skope · <model>`, an optional tool line
  (`Read table.pg-table · 7 rows`, spinner while running), streaming cursor, and
  an error row with **Retry**.
- **Notes** tab: page-linked notes (favicon, title, URL, time), optional
  highlighted quote (from text selection → **Save note**), body, hover actions
  copy / open source / delete; search; a composer pinned at the bottom.
- Considered and rejected for now: forking a thread to another model. The
  useful kernel — "ask another model about *this* answer", rendered as a second
  answer under the first with "Continue with X" — is a good later addition.

## 4. Model source

```
Source        AI Skope Server (default)            | API keys (direct)
Runtime       Claude Code · Codex · pi/omp/opencode | provider (Anthropic, OpenAI, Google, Ollama)
Model         runtime's models; for pi/omp/opencode a shared provider registry
              (z.ai / GLM 5.3, fireworks.ai / Kimi K2, ollama / qwen3 …)
Effort        Low / Medium / High / Max — per runtime, only via server
```

- **Model chip** (in the composer): runtime glyph · model name · effort tag
  (hidden under 440 px) · status dot. Latency and full path live in the tooltip
  (`pi · z.ai / GLM 5.3 · High · via AI Skope Server`) and in the switcher.
- **Switcher** rises from the chip: source segmented control, a server line
  (`localhost:7331 · connected · 5 runtimes · v0.3`), search, groups per runtime
  (pi · omp · opencode share a group with a runtime chooser), rows with status
  dot, `provider / model`, latency · context size, tags (default, on device), an
  **Effort** row when the runtime supports it, and **Manage sources →**.
- **Status**: dot ok / degraded / offline; a strip above the composer when
  unusable: "AI Skope Server isn't reachable — retrying in 4s · **Use API keys**"
  (or "<model> is offline — Switch model" in keys mode). Send is disabled.
- pi, omp and opencode are treated as one family because they consume the same
  provider registry; the user picks which of the three executes.

### Add a source (three paths)
1. **Runtime on the server** — detected agents with version and path, enable
   switch, "Install guide" for missing ones, custom command (`my-agent --stdio`).
2. **Provider via server** (default) — provider (z.ai, fireworks.ai, OpenRouter,
   Groq, Together, custom OpenAI-compatible), key stored **by the server**,
   "Available to" pi / omp / opencode, key test showing models found.
3. **API key (direct)** — stored in extension storage; calls go straight to the
   provider; no server, no local files.

## 5. Settings — two tiers

**In-pane sheet (quick, no scrolling):** Theme (Light/Dark/System), Color
(6 palettes), Text size, Pane side, Open automatically, Model source toggle,
Server summary → Manage, Providers summary → Manage, Page access, Blocked sites
summary → Manage, "All settings ↗".

**Full settings page (extension options tab):** sticky left nav — General
(with the **Setup checklist**: install server · allow a folder · choose default
runtime), Server & runtimes (URL, status, restart, logs, runtimes table,
custom command), Folders (table: path, indexed count, access Read / Read+watch,
last indexed, remove; Add folder; ignore rules), Providers & keys (via server
table with "available to", Add a source as a dialog; direct keys table),
Privacy (page access, blocked sites, keep history, retention, export, clear),
Shortcuts (editable), About (versions, update).

## 6. Visual system

Direction **"optical instrument"**: cool graphite neutrals with a blue-teal
bias; **amber is reserved for aim** (picked outline, selection tint, chips,
send); teal for focus/links; green/amber/red only for status. Manrope (UI),
IBM Plex Sans (body), IBM Plex Mono (selectors, latency, shortcuts). Radii
6 / 10 / 14. Shadows only on floating things. Motion 120–220 ms, reduced-motion
respected. The reticle is both the app mark and the picker cursor.

Six palettes orthogonal to light/dark: Graphite (default), Nocturne (indigo +
brass), Sage (green-grey + terracotta), Ember (warm charcoal + coral), Arctic
(ice blue + cool amber), Mono (greys + electric blue). Tokens in
`design/tokens/tokens.css`, palettes in `design/tokens/themes.css`, components
in `design/tokens/components.css` (`sk-*` classes). Three theme states must
resolve (bare `:root`, `prefers-color-scheme`, explicit `data-theme`).

## 7. Implementation assumptions for the extension (next wave)

- **Manifest V3.** The split canvas is done by the extension wrapping the tab:
  either Chrome's Side Panel API (simplest, but fixed to Chrome's side-panel
  width rules) or an injected top-level layout where the page lives in the
  content area and the AI Pane is an extension iframe. Decide in wave 2 after a
  spike; the design assumes a resizable pane and full-height layout, which the
  Side Panel API does satisfy.
- A **content script** handles pick mode (hover/outline/tag/selector
  generation), text selection + floating toolbar, and page-text extraction; it
  talks to the pane via `chrome.runtime` messaging.
- **Local pages**: `file://` URLs require the user to enable "Allow access to
  file URLs"; the extension maps the URL to a path the server may already index.
- The pane talks to the server over `http://127.0.0.1:7331` with a pairing
  token; streaming via SSE. No page content leaves the machine unless a direct
  API key is in use or a server-side provider is cloud-hosted — the Page access
  setting governs whether whole-page text is sent at all.
- Extension storage holds: settings, direct API keys, pairing token, palette /
  theme. Chats, notes, folders, server-side keys live in the server's SQLite.

## 8. Open questions

1. Effort levels differ per runtime (Claude Code has Max; pi does not) — the
   server must advertise them per runtime/model.
2. What exactly is **omp** (binary name, JSON output mode)? Treated as a
   pi-family agent in the design; confirm before writing its adapter.
3. Side Panel API vs injected layout (see §7).
4. Should the extension work at all without the server (keys-only mode)? Design
   says yes, as a degraded path.
5. Retention / export format for chats and notes.
